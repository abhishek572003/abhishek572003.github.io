Current work: an open research notebook

Do AI coding agents introduce more cloud security misconfigurations than people do when they change infrastructure code?

Coding agents such as Claude Code, Copilot, Codex, and Devin now open a growing share of pull requests on GitHub, including changes to Terraform and Kubernetes files that decide who can reach what. Recent work compared agent and human infrastructure changes for maintainability, but not for security. I am measuring that gap.

  1. Find pull requestsAgent-authored changes to .tf and Kubernetes YAML, each matched with human changes in the same repository.
  2. Rebuild both versionsEvery changed file at the base commit and the head commit.
  3. Scan the differenceCheckov and KICS on both versions. Only checks that fail after the change count as introduced.
  4. Validate and compareHand-label a sample for false positives, then compare matched pairs by category: IAM, network exposure, encryption, container privilege.
  1. 21 Nov 2026Framed the question after a literature review of 13 papers. The closest prior study measured sustainability smells only.
  2. 21 Nov 2026Pilot pipeline runs end to end on 9 pull requests. Too small to draw conclusions, but it showed that matching on change size is needed.
  3. Dec 2026Next: scale to 500+ agent pull requests and add Kubernetes manifests and a second scanner.
  4. Feb 2027Goal: a preprint with code and data released.
